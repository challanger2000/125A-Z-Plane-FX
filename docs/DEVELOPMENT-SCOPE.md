# Development contract — 125A Z-Plane FX v0.1.0

Repository: challanger2000/125A-Z-Plane-FX. New product, no owner-approved release; branch develop/v0.1.0. Main contains historical tooling only.

## Current implementable scope
- Stereo-in/stereo-out VST3 audio effect, 32- and 64-bit host sample buffers.
- Independently implemented, textbook normalized biquad LP/HP/BP/notch modes, NOT E-MU X3 filters.
- Parameter IDs: 0 mode, 1 cutoff, 2 resonance, 3 wet, 4 bypass. Stable across subsequent compatible iterations.
- Dry/Wet and bypass reach exact dry identity after their documented 5 ms transition; filter-mode/cutoff/Q changes use 5 ms dual-engine crossfades. No allocation/locks/I/O in the audio callback.
- Generic host parameter UI only for now.
- Save and recall parameters (versioned format).
- Regression: impulse, silence, sample partition, 2-channel isolation, dry/bypass steady-state identity, invalid parameter bounds, real native VST3 state roundtrips, truncated-state rejection and Release-mode unconditional assertions.

## Future fidelity gate
- Do NOT import research code or extracted E-MU tables without an explicit appropriate rights basis.
- Need explicit independent 55-filter reference source and bank provenance. The validated research results are scientific evidence, not an automatic copyright license.
- Implement and compare all 55 filters against the authorized baseline before calling any future candidate "Z-Plane accurate".
- Add modulation, morphing, dynamic ramps, native GUI only after core verified.
- Need Steinberg validator, 125A Plugin Tester, DAW and ASIO, actual audio fixtures and user listening prior to FINAL.

## Known limitations
Prototype does not emulate X3 filter types, native coefficient tables, morph designer, adaptive gain or hardware. Parameter changes support individual host sample offsets, bounded to 4096 event points per process block. All final release gates NOT VERIFIED.

## Cross-family host-block invariance and rapid retarget regression — 2026-11-08

Six independent CTests and 47/47 Validator cases still passed, proving this was a missed cross-family state-lifetime contract, not generic VST3 validation failure.
- **Root cause:** Once the 240-sample family crossfade ended inside a long host segment, the entire preselected 128-sample scratch loop continued processing *both* DSP engines through the rest of that host segment. - Source fix `c95d67d17c5787c493c5d2020a3efadc801d0525` prevents any sample past the fade's exact end from reaching the inactive DSP family. It bounds a scratch chunk by `familyLeft_` and returns to the single-engine fast path at the first sample after completion. No callback allocation, lock or I/O was introduced by this fix.
- Extra independent fixture `fa85bd6b64010dd00f0db304cb66846626e91bbb` compares a sequence of **seven** X3↔Legacy host edits, including reversals before the preceding 240-sample fade completes, against an independently constructed E-MU-filter + textbook-biquad + per-sample crossfade reference. ## Queued X3 Morph/Q filter timing: reproduced defect and sample-exact repair — 2026-11-08

- **Defect reproduced:** adversarial test-only source `c0c87c6d5f5f061a148f56162bdbe20b7a6590cd`, [Windows Actions #42537143129](https://github.com/challanger2000/125A-Z-Plane-FX/actions/runs/42537143129) **FAIL** in native staged VST3 at **sample 410**: one 4,096-frame process callback produced left PCM **−0.00484927**, irregular host partitions **−0.00484392** for identical in-block Morph/Q automation. Six CTests and 47 official Steinberg tests remained PASS. The same commit extended the keyboard menu test to iterate **all 55 X3 entries** and all **four** Legacy menu entries, validating every normalized step and host edit; the run reached the DSP negative-control failure, not a menu-test failure.
- **Root cause:** `X3ResearchAdapter::completeDeferred()` started a queued filter-coefficient transition only when the processor next entered a host/parameter segment. A running 5-ms filter fade could finish *inside* an audio segment; the start of its queued successor then shifted depending on arbitrary host callback boundaries. This is distinct from the previously repaired Legacy↔X3 family fade lifetime defect, but violates the same sample-time invariant.
