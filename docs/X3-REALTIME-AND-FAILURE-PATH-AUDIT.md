## Real Windows counterexamples and corrected functionality

- **Heap/throw probe:** new Windows native executable `tests/X3RealtimeAuditTests.cpp` instruments global C++ `new`, `new[]`, aligned new and the direct header-only research adapter's `set()`, `process()`, `completeDeferred()`. Real bank fixtures were loaded **before** the guarded thread section. **55 filters × 4 sample rates × 6 Morph/Q cases = 1,320**, including queued filter transitions, 32/64-bit buffer routes and bypass/Wet. [Original 7/7 CTests and 47/47 validator PASS #42544763474](https://github.com/challanger2000/125A-Z-Plane-FX/actions/runs/42544763474): **0 observed C++ new calls, 0 C++ exceptions, 0 nonfinite samples** in this measured ordinary-signal domain.
- **Reproduced failure** [RED #42545740367](https://github.com/challanger2000/125A-Z-Plane-FX/actions/runs/42545740367): with a *finite* `float` maximum input, original X3 Filter 1 at 44,100 Hz produced `+Inf/-Inf` already at sample 1, risking persistent NaN/Inf IIR feedback. (An earlier harness build [#42545502803](https://github.com/challanger2000/125A-Z-Plane-FX/actions/runs/42545502803) was a test-only Windows NOMINMAX compile issue, not audio evidence.)
- **Fix** `ae18ce734534c30b402c14b91aa7e4ed7cc34293`: the *locally owned* `X3ResearchAdapter` now sanitizes the outputs and recursively stored state of both main/next filters on nonfinite values, and prevents 64-bit host inputs outside the float32 domain from reaching the original Float32 DSP. The correction leaves all normal, in-range research PCM arithmetic bit-identical. Before float narrowing, compare with `std::numeric_limits<float>::max()` in double to avoid raising an unnecessary hardware float overflow on the host.
- [GREEN #42546068439](https://github.com/challanger2000/125A-Z-Plane-FX/actions/runs/42546068439): **7/7 CTests, 47/47 Validator, 2,640/2,640 independent original-research PCM cases**, and **220/220 X3 filters × sample rates** both after finite float32-max abuse and finite double-max abuse, checking full-buffer finite output and subsequent normal-impulse state recovery. No external research header was patched or vendored.
- **Concurrent saved-state hazard:** `Processor::getState` previously read ordinary `params_` values while the audio callback wrote to them, a C++ data race permitting a torn parameter set. Source commit `35167cc347274f59a2a295462c504d67962413a9` introduces fixed-size, **lock-free atomically published six-parameter snapshots**, with bounded coherent readers on control threads, preserving audio-thread-owned `params_`. The native real-Windows VST3 host additionally saves project state while actively editing all six parameters.
- [Native concurrent state verification #42546805991](https://github.com/challanger2000/125A-Z-Plane-FX/actions/runs/42546805991): **5,000 native audio callbacks**, **8,000 coherent six-parameter project saves**, no mixed generations and no rejected saves. All seven CTests, 47/47 validator and 2,640/2,640 PCM reference cases PASS; cloud 48 kHz/256 measurements over 180 callbacks max **0.0467 ms**, **0** callback overruns/scheduler-late starts. **Not hardware ASIO or a worst-case execution-time proof.**

## Unverified areas and release blockers

1. These C++ allocation hooks detect header-inline C++ `operator new` calls only; **direct C `malloc`, Win32 `HeapAlloc`, transitive runtime behaviors and other DLL allocations are not dynamically intercepted**. Source-level inspection of the used headers supports bounded static-state operations, but a full independent binary-level allocation/lock audit remains open.
2. Actual hardware ASIO/ETW callback timing, multi-core scheduling pressure, CPU denormals and unmasked FP exception behavior remain **NOT RUN** on the owner's target DAW/computer. A cloud benchmark is not certification.
3. `Processor::setState` requires the normal VST3 host lifecycle with audio processing suspended; concurrent *setState plus process* is not certified. Concurrent *getState plus process* has the explicit successful test above.
4. X3 source supports 44.1/48/96/192 kHz. Other host rates, independent E-MU hardware sound-matching, uninterrupted DAW playback, full GUI/HiDPI owner acceptance, and original X3 commercial redistribution rights remain **NOT VERIFIED**.
5. These are scoped component and integration checks, not complete 125A `QA/AUDIT-COMPLETENESS-CONTRACT.md` evidence. **No FINAL, no release approval, no implied permission to ship the third-party code or reconstructed filter-bank data.**

## Bank-load failure invalidation: stale X3 IIR defect and Windows RED→GREEN — 2026-11-09

- **Original code defect:** In `X3ResearchAdapter::load()`, the `catch(std::exception)` cleanup cleared `factory_` and `extended_` but **did not call `reset()`**. A previous successful load left `initialized_=true` and live primary/secondary IIR filter state. If a later reload failed because a bank was missing or truncated, `hasBanks()` correctly returned false but `process()` continued rendering the **stale old-bank filter**. An apparently rejected bank could therefore still produce sound from disallowed/old coefficients.
- **Independent falsifying test:** [RED Windows #42548064789](https://github.com/challanger2000/125A-Z-Plane-FX/actions/runs/42548064789), test-only commit `a7c9ad90e4f3dbf9721cedff06261c82e0fbd769`, exercised a good synthetic bank, armed X3 mode 1, removed `factory-bank.bin`, called `load()` (expected false), then checked that output sentinel values remained untouched. The native CTest failed at `X3 FAIL: s==17.5f at 50` proving stale DSP still executed. This is a reproducible adapter lifecycle defect, NOT an assertion about legal/illegal filter-bank content. No proprietary E-MU data required.
- **Owned-source repair:** [commit `1b7d872`](https://github.com/challanger2000/125A-Z-Plane-FX/commit/1b7d872421df39bb3f0f09a5770e8bfd2cc7bc40) adds the fixed-size `reset()` before clearing bank pointers in the catch branch. This is explicitly **control-thread only** before setActive, not a new audio-callback operation. A failed reload now leaves `initialized_=false` and cannot render the previous DSP; a later valid reload is able to reinitialize normally.
- **First positive Windows verification:** [GREEN #42548302872](https://github.com/challanger2000/125A-Z-Plane-FX/actions/runs/42548302872), exact repaired commit `1b7d872421df39bb3f0f09a5770e8bfd2cc7bc40`: native synthetic bank missing/truncated negative tests and subsequent recovery **PASS**; **7/7 CTests**, **47/47 Steinberg Validator**, **2,640/2,640 original research X3 PCM references**, all native GUI/automation and concurrent-state tests **PASS**.

Cloud 180 callbacks, 48 kHz/256, p99 **0.0319 ms**, max **0.0439 ms**, 0 deadline overruns and 0 late starts. **No physical ASIO certificate.** The bank tests verify the three original research bank filename/length failure cases, not a complete hostile-data parser fuzzing exercise.
